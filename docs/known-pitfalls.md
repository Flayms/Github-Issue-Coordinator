| A read-only git command can run any command                             | `git grep -O<cmd>` (`--open-files-in-pager`) runs `<cmd>`, so allowing `Bash(git grep:*)` would let the Planner and Reviewer run arbitrary shell, including the PR's code. Check any other git subcommand for pager, exec or output options before allowing it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | fixed      |
| Read-only git can write files                                           | `git log`, `git show` and `git diff` accept `--output=<file>`, so the Planner's and Reviewer's allowed `Bash(git log:*)` etc. could create or overwrite files: the sandbox lets shell commands write to the cwd, which for the Planner is the main clone the Coordinator later runs git in unsandboxed. With `--format=%B` the content can be a commit message from a PR (#23)                                    | Their sandbox now sets `sandbox.filesystem.denyWrite` to their cwd (deny beats the default cwd allow), so their shell can write only to the session folder and the sandbox's temporary folder (REQ-001-25). Prefix rules can't deny the flag, it can come anywhere. Audit of the other allowed subcommands (`status`, `ls-files`, plus `log/show/diff`): no other option writes a file; the pager, `--ext-diff`/`--textconv` and diff drivers all come from git config, which Claude Code's sandbox write-protects (`.git/config`, `.git/hooks`) and which is now inside the denied cwd anyway; `git -c …` or `GIT_PAGER=… git …` doesn't match the `Bash(git log:*)` prefix. That stays safe only as long as no Role can write the config. A real sandboxed run (`bun scripts/smoke-runner.ts --role reviewer`) is still to be recorded | fixed      |
