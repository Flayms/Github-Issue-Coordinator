# Known pitfalls

Problems hit during development — either to avoid them in the future or to fix later on.

| Pitfall                                                                 | Symptom                                                                                                                                                                                                                                                                                                                                                                                                           | Workaround / fix                                                                                                                                                                                                                                                                                        | Status     |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Folder trust dialog on every new directory                              | An interactive `claude` started in a new folder (e.g. a fresh Worktree) stops at "Is this a project you created or one you trust?" with "No, exit" preselected. Seen in the T0 spike, Claude Code 2.1.322                                                                                                                                                                                                         | Verified: detect the dialog in `tmux capture-pane` and answer with `tmux send-keys Down`, then `Enter`. Untested alternative: pre-trust the path in `~/.claude.json` (`projects[<path>].hasTrustDialogAccepted`, spike `--pretrust`)                                                                    | workaround |
| A blocked stop shows as "Stop hook error"                               | When the `Stop` hook blocks to demand a valid Result, the session UI (and the phone) shows "Stop hook error". The session still continues correctly                                                                                                                                                                                                                                                               | Cosmetic; word the block reason so it reads as an instruction, not a failure                                                                                                                                                                                                                            | accepted   |
| Subscription login expiry                                               | `claude auth status` reports a `loginExpiresAt` about 2 weeks out                                                                                                                                                                                                                                                                                                                                                 | Unknown whether it auto-refreshes; the Coordinator should check `claude auth status` and warn before expiry                                                                                                                                                                                             | open       |
| CI that reports commit statuses, not check runs                         | The App only has `Checks: read`, so `GitHubClient.checks` sees check runs (GitHub Actions and most apps) but not legacy commit statuses; such a PR looks like it has no checks and gets reviewed straight away                                                                                                                                                                                                    | Add `Commit statuses: read` and merge `GET /commits/{sha}/status` into the checks summary if a managed repo needs it                                                                                                                                                                                    | open       |
| Permission prompts stall unattended sessions                            | In the T6 smoke test, haiku wrote its Result with a Bash heredoc instead of the Write tool and stopped at "Do you want to proceed?" until timeout. The `Notification` hook fires with `notification_type: "permission_prompt"`                                                                                                                                                                                    | The Result instructions now ask for the Write tool. Still open: per-Role allowed tools (T7) and surfacing `permission_prompt` sessions (the Owner can answer from the phone; otherwise they hold a Slot)                                                                                                | open       |
| Usage-limit detection is unverified                                     | The hook treats a final transcript entry with `isApiErrorMessage: true` mentioning "limit" as the usage limit. The real shape has not been seen yet                                                                                                                                                                                                                                                               | Every hook payload is logged to `state/sessions/<id>/events.jsonl`; check it the first time a limit is hit and adjust `usageLimitText`                                                                                                                                                                  | open       |
| Main clone is reset under a running Planner                             | Each Planner pass or revision fetches and hard-resets the repo's main clone. With `maxPlanners` above 1, a Planner that is still reading it could see files change                                                                                                                                                                                                                                                | Keep `maxPlanners: 1` (the default), or give each Planner its own checkout if parallel planning is needed                                                                                                                                                                                               | open       |
| Old Claude Code versions pile up                                        | The auto-updater keeps every version in `~/.local/share/claude/versions/` (about 330 MB each); on the 4 GB / 38 GB server, 4 versions took 1.3 GB in one account                                                                                                                                                                                                                                                  | Delete all but the version `~/.local/bin/claude` points to, for each user (`anton`, `agent`). Could become a periodic cleanup in the Coordinator                                                                                                                                                        | open       |
| `bun: command not found` as the agent user                              | `sudo -iu agent bash -lc 'bun …'` fails: the Bun and Claude installers only extend `~/.bashrc`, which non-interactive shells skip                                                                                                                                                                                                                                                                                 | `deploy/create-agent-user.sh` adds both to `~/.profile`; the systemd unit sets `PATH` itself                                                                                                                                                                                                            | fixed      |
| Sandbox was silently off, then blocked by Ubuntu's AppArmor             | Without `socat` the sandbox quietly stayed off (the T7 smoke run "worked" unconfined). With `socat` installed, every Bash call failed on Ubuntu 26.04: `apply-seccomp: write /proc/self/setgroups (nested userns is capability-restricted …)`, because `/etc/apparmor.d/bwrap-userns-restrict` runs everything inside bwrap as `unpriv_bwrap` with `deny capability`. Found by issue #1, the first dogfooding run | Implementer settings now set `failIfUnavailable` and `allowUnsandboxedCommands: false`, so the sandbox can never be silently off. Replace Ubuntu's bwrap profile with the one from the Claude Code sandboxing docs (docs/setup.md step 1); `bun run doctor` checks it                                   | workaround |
| Read-only git can print any file                                        | `git diff --no-index <file> /dev/null` shows any file the user can read, so allowing `Bash(git diff:*)` gave the Planner and Reviewer a way to read the GitHub App key                                                                                                                                                                                                                                            | All Roles run their shell commands in the sandbox with the secrets in `sandbox.filesystem.denyRead`, plus `Read(...)` deny rules for the file tools (REQ-001-26)                                                                                                                                        | fixed      |
| No `/etc/apparmor.d/disable/` on Ubuntu 26.04                           | Linking Ubuntu's `bwrap-userns-restrict` into `disable/` fails ("No such file or directory"); the later commands still load Claude's profile, so it works until the next boot, when Ubuntu's profile (same name `bwrap`) can win again                                                                                                                                                                            | `sudo mkdir -p /etc/apparmor.d/disable` first (docs/setup.md step 1); `bun run doctor` checks the link                                                                                                                                                                                                  | fixed      |
| A failed sync left the issue stuck, then failed it for the wrong reason | Issue #1, second dogfooding run: the Implementer committed and the branch was pushed, but creating the PR failed with `403 Resource not accessible by integration` (the App installation lacked **Pull requests: write**). The sync was never retried; 30 min later the idle session was closed and the issue failed with "no implementer session to resume"                                                      | A failed sync is now retried every tick, also after its session was closed, and after 3 attempts in a row the issue gets `agent:failed` with the real error (REQ-001-27). For the 403: grant the App **Pull requests: read & write** and accept the new permissions on the installation (docs/setup.md) | fixed      |
| A conflicted PR looked like a PR without checks | Issue #6: GitHub does not run `pull_request` workflows on a PR with merge conflicts, so `checks()` returned "none", which counted as passed. The PR was reviewed and left with its conflicts. Right after a push, "none" also just meant CI had not registered its runs yet | The Coordinator reads the PR's `mergeable`: conflicts start a Feedback round (REQ-001-28), and no Review runs until it is `true` (GitHub computes it lazily, so the first read may be `null`). "No checks" counts only after `checksGraceSeconds` (REQ-001-10) | fixed |
| Biome fails on files the sandbox hides | Inside an Implementer's sandbox, `bun run lint` reports `Permission denied (os error 13)` for untracked `.mcp.json` and `.claude/settings.local.json`, which the sandbox denies reading | Not caused by the change under test; run `bunx biome check $(git ls-files '*.ts' '*.json')` and `tsc --noEmit` to lint the tracked files | open |
