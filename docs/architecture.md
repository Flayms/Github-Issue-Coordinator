# Architecture

One Bun process, the Coordinator, runs a reconcile loop. Every `pollIntervalSec` it lists each configured repository's open issues and PRs, and the head branches of its open PRs (both with an ETag), works out the desired action for each item from its `agent:*` labels and the local store, and hands actions to a scheduler with per-Role Slots. Agents are interactive `claude` sessions in detached tmux windows, registered with Remote Control so the Owner can follow them from the Claude app. The Coordinator runs on a VM of its own, and agents run there unrestricted: permission prompts skipped, no sandbox, `sudo` allowed (spec 005). The only GitHub credential is the fine-grained PAT the GitHub CLI is logged in with; the Coordinator reads it with `gh auth token` and agents use `gh` as the same user (REQ-005-02). The Coordinator does every GitHub write, including creating the Split-off issues a Planner proposes in its Result (REQ-001-34), and reads for agents what they need from GitHub, such as the Linked history of issues and PRs an issue to plan links to (REQ-001-47); agents read anything else with `gh` and leave writes to the Coordinator (REQ-005-04). Since the PAT may be the Owner's own, the Coordinator's posts carry the Owner's id; Owner input is what the Owner wrote without an agent note (REQ-005-03). Details and rationale: `docs/specs/001-issue-coordinator/plan.md`.

```mermaid
flowchart LR
  GH[(GitHub)] <-- REST, PAT from gh --> C[Coordinator]
  C --> S[(bun:sqlite store)]
  C -- tmux + claude --remote-control --> A[Agent sessions<br/>Planner / Implementer / Reviewer]
  A -- hooks --> S
  A -. Remote Control .-> P[Owner's Claude app]
  C -- Tick snapshot --> D[Dashboard<br/>read-only, loopback]
  D -. Tailscale / SSH tunnel .-> P
```

At the end of every tick the Coordinator publishes a Tick snapshot (issues, agent PRs, sessions, the queue with wait reasons, the recent Events). Whenever the Coordinator acts on GitHub (an Assessment, an approval, a block, an agent PR, a Review, a Feedback round, a failure) it records an Event in the store, capped at 200 (REQ-003-15). The dashboard (on by default, [spec 003](specs/003-dashboard/spec.md)) serves only that snapshot: no GitHub calls, no store writes.

## Modules

| Module                         | Responsibility                                                                                                                                                                                                                                                                                                      | Status   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `src/index.ts`                 | Entry point (`bun start`): wires everything, runs the loop, checks for dialogs every 3s                                                                                                                                                                                                                             | T15 done |
| `src/coordinator.ts`           | Reconcile loop: sync finished turns, poll (incl. head, checks and mergeability of agent PRs), derive, schedule across repos, execute                                                                                                                                                                                | T15 done |
| `src/git.ts`                   | Main clone per repo, reset to the default branch; the token is passed per command, never stored                                                                                                                                                                                                                     | T15 done |
| `src/implementer.ts`           | Implementer start (Bundle, Worktree, limited context), push + PR after every turn (with Screenshots, REQ-001-49/50), cleanup after merge/close, re-attach of orphaned agent PRs                                                                                                                                     | T11 done |
| `src/reviewer.ts`              | Reviewer start on a PR-head checkout, one COMMENT review, labels, session closed afterwards                                                                                                                                                                                                                         | T12 done |
| `src/note.ts`                  | The agent note heading every comment, PR and review; recognising it, so the Coordinator's posts are not Owner input (REQ-005-03)                                                                                                                                                                                    | T11 done |
| `src/worktrees.ts`             | Worktree per issue/Bundle (local clone + new or existing remote branch + setup), push, fetch of the default branch for merge-conflict rounds, Screenshot publishing to the orphan branch `agent-screenshots`, review checkouts, removal                                                                             | T10 done |

| `src/github/gh-token.ts`       | REQ-005-02: the GitHub CLI's PAT (`gh auth token`), read again every 5 minutes; the one GitHub credential                                                                                                                                                                                                           | done     |

| `src/store.ts`                 | `bun:sqlite`: sessions (Role, issues, Claude session id, state, Account), the usage-limit pause per Account, per-issue bookkeeping, Split-off issues and the newest 200 Events                                                                                                                                      | T4 done  |

## Tech Stack

| Concern | Technology                                | Purpose                                                                          |
| ------- | ----------------------------------------- | -------------------------------------------------------------------------------- |
| Runtime | Bun, TypeScript                           | Daemon, hook scripts, tests (`bun test`)                                         |
| Lint    | Biome, `tsc --noEmit` (TypeScript 7)      | Formatting and linting (code and Markdown), types                                |
| Config  | zod                                       | Validate `config.ts` (later also Result files)                                   |
| GitHub  | REST API with a fine-grained PAT via `gh` | The one GitHub credential on the VM                                              |
| Agents  | Claude Code CLI, tmux, Remote Control     | Interactive sessions the Owner can follow                                        |
| State   | `bun:sqlite`                              | Session ids, Worktrees, rounds (T4)                                              |
| Service | systemd on an Ubuntu VM                   | `deploy/setup-vm.sh`, `deploy/github-issue-coordinator.service`, `docs/setup.md` |
